1. INTRODUCTION

Reawakened Hills is a full-stack web application designed to address one of the most critical socio-economic challenges in Uttarakhand: the migration crisis and the emergence of deserted "Ghost Villages" (Bhootaha Gaon). Over the last two decades, economic hardship and agricultural stagnation have forced thousands of native families to leave their ancestral heritage cottages.

Concurrently, mainstream tourist destinations such as Mussoorie, Nainital, and Rishikesh face excessive congestion and inflated commercial hotel tariffs during peak seasons and the annual Char Dham Yatra. Travelers increasingly seek authentic, peaceful, and culturally rooted Himalayan homestays, yet native villagers lack a modern digital platform to list and monetize their vacant ancestral properties.

Reawakened Hills bridges this divide by delivering a direct, transparent marketplace connecting rural hosts with travelers, trekkers, and pilgrims. The application removes bureaucratic delays through instant host publishing, mandatory multi-photo verification (minimum 3 photos), interactive Google Maps coordinates, simulated multi-channel payments (UPI, Card, Net Banking), real-time host notifications, and an automated cancellation engine with 50% / 100% refund tiers.

Objectives
  • To revitalize vacant ancestral heritage homes across ghost villages in Uttarakhand.
  • To empower native hosts to list and manage homestays with mandatory multi-photo verification.
  • To provide travelers with a high-speed discovery engine filtering stays across all 13 districts.
  • To integrate exact Google Maps navigation coordinates and verified amenity showcases.
  • To simulate a realistic multi-channel payment gateway supporting UPI, Card, and Net Banking.
  • To generate official booking confirmation receipts with unique transaction references.
  • To deliver real-time host notifications displaying guest contact details and earnings summaries.
  • To implement an automated cancellation engine with transparent 100% and 50% refund tiers.
  • To provide curated static intelligence guides for the Char Dham Yatra and 26 offbeat hidden gems.
  • To maintain application data securely within a normalized standalone MySQL database.

2. SCOPE OF THE PROJECT

The scope of Reawakened Hills encompasses the end-to-end design, database modeling, API implementation, and presentation of a Himalayan cultural homestay portal.

Main Functional Scope
  1. User Authentication: Cryptographic password hashing (`bcryptjs`) and role support for Tourists, Village Hosts, or dual Host-Travelers.
  2. Ancestral Home Publishing: Direct host onboarding capturing property titles, villages, districts, nightly rates, and descriptions.
  3. Multi-Photo Verification: Enforces minimum 3 and maximum 5 verified photographs per stay (Exterior, Room Interior, Extra View) via `multer`.
  4. Stays Discovery & District Filter: Search engine allowing tourists to filter stays across all 7 Garhwal and 6 Kumaon districts.
  5. Property Showcase & Amenities: Interactive photo carousel, verified amenities (Wi-Fi, parking, kitchen, heating), and host profiles.
  6. Google Maps Navigation: Direct map links for precise GPS navigation across remote mountain terrains.
  7. Stay Reservation Engine: Date range pickers, night calculation, and live pricing breakdowns.
  8. Dummy Payment Gateway: Simulated authorization for UPI (autofill VPA), Credit/Debit Cards, and Net Banking.
  9. Booking Confirmation Voucher: Official receipts featuring booking references, host details, and print capabilities.
  10. Host Notification Dashboard: Live alert banners notifying property owners of confirmed reservations with traveler contacts.
  11. One-Click Host Communication: Direct WhatsApp integration with pre-filled greetings and phone call links.
  12. Automated Cancellation & Refunds: Early cancellations (2+ days prior) yield 100% refunds; 1-day prior cancellations deduct 50% for host compensation.
  13. Listing Management: Hosts can modify prices, update descriptions, replace photos, or delist properties.
  14. Curated Guides: Standalone static guides for the Char Dham Yatra and 13-district offbeat hidden gems.
  15. Responsive Design: Fluid mobile-first Bootstrap 5 interface engineered for low-bandwidth connections.

3. REQUIREMENTS OF THE PROJECT

3.1 Functional Requirements
  • Authentication: Secure registration and login with duplicate email protection and salted password hashes.
  • Listing Verification: Enforcement of 3–5 uploaded photos and automatic Photo Verified trust badge assignment.
  • Reservation Processing: Server-side date range verification, night calculation, and dummy payment gateway simulation.
  • Host Tracking: Filtering bookings by `host_id` to present full guest names, phones, and earnings on host dashboards.
  • Cancellation Algorithm: Dynamic day difference calculation between cancellation date and `check_in` executing 100% vs 50% refund allocations.
3.2 Non-Functional Requirements
  • Security: All SQL queries parameterized with placeholders (`?`) preventing SQL Injection. Passwords hashed via `bcryptjs`.
  • Performance: Sub-80ms API response latency utilizing MySQL connection pooling; lightweight client loads under 1.5s.
  • Reliability: Dual-mode architecture featuring standalone MySQL with fallback in-memory data persistence.
  • Usability: Authentic Himalayan color scheme, high-contrast typography, and intuitive modal dialogs.

6. CODE LISTING SAMPLE

Stay Cancellation & Dynamic Refund Handler (`server.js`)
const handleBookingCancellation = async (req, res) => {
    try {
        const id = parseInt(req.params.id, 10);
        const [rows] = await db.query(`
            SELECT b.*, p.title as property_title, p.village, p.district, p.host_id
            FROM bookings b LEFT JOIN properties p ON b.property_id = p.id
            WHERE b.id = ?
        `, [id]);

        if (!rows || rows.length === 0) return res.status(404).json({ error: 'Reservation not found.' });
        const booking = rows[0];
        if (booking.status === 'cancelled') return res.status(400).json({ error: 'Already cancelled.' });

        const totalAmount = parseFloat(booking.total_amount) || 0.00;
        const checkInDate = new Date(booking.check_in);
        const checkInMidnight = new Date(checkInDate.getFullYear(), checkInDate.getMonth(), checkInDate.getDate());
        const todayMidnight = new Date(new Date().getFullYear(), new Date().getMonth(), new Date().getDate());

        const diffDays = Math.round((checkInMidnight - todayMidnight) / (24 * 60 * 60 * 1000));
        let refundPercentage = 100, deductionAmount = 0.00, refundAmount = totalAmount;

        if (diffDays >= 2) {
            // Early cancellation (2+ days prior): 100% Full Refund
            refundPercentage = 100;
            deductionAmount = 0.00;
            refundAmount = totalAmount;
        } else if (diffDays >= 0) {
            // 1 day before stay: 50% deduction, 50% refund
            refundPercentage = 50;
            deductionAmount = Math.round((totalAmount * 0.5) * 100) / 100;
            refundAmount = Math.round((totalAmount * 0.5) * 100) / 100;
        } else {
            // Past check-in date: Non-refundable
            refundPercentage = 0;
            deductionAmount = totalAmount;
            refundAmount = 0.00;
        }

        const reason = req.body.reason ? String(req.body.reason).trim() : 'Schedule change';
        await db.query(`
            UPDATE bookings 
            SET status = 'cancelled', refund_amount = ?, deduction_amount = ?, cancellation_reason = ?, cancelled_at = NOW(), payment_status = ?
            WHERE id = ?
        `, [refundAmount, deductionAmount, reason, refundAmount > 0 ? 'refunded' : 'cancelled', id]);

        res.json({
            success: true,
            message: `Reservation cancelled. Refund of ₹${refundAmount.toLocaleString('en-IN')} processed.`,
            cancellation: { booking_id: id, refund_amount: refundAmount, deduction_amount: deductionAmount, status: 'cancelled' }
        });
    } catch (err) {
        res.status(500).json({ error: err.message });
    }
};
